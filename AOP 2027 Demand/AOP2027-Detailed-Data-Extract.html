Finance Attribution — Methodology

Calculation logic used in the Navigator. No actual portfolio values are shown here. For programme costs and allocation outcomes, use the Program Data tab.

Two Pillars of IT Cost

Pillar 1 — Programme Demand

Competitive IT investment demand from BUs and F&R. Allocated through the prioritisation engine using merit ranking and lever-controlled stage targets. Configurable via levers and manual decisions.

Pillar 2 — Operations (TCO)

Pre-aligned cost of running existing IT. Fixed and read-only — does not change with programme decisions. Sourced from the Bill of IT workbook.

Total IT AOP = Prioritised Programme AOP + Operations AOP

Total AOP changes ONLY when the user manually edits the budget input. ExCo trade-off Apply buttons never modify Total AOP.

Programme Cost Flow

1
Source requested amount: K€ in source ÷ 1000 = M€ in modeler
2
Classification into P1/P2/P3/P4 based on source evidence fields (deterministic — cannot be overridden by levers)
3
Lever-controlled stage targets: each stage has an independent target (% bucket, % AOP, or M€ amount)
4
Whole-programme allocation in merit ranking order — no partial splits by engine
5
Final prioritised amount per programme → organisation-level allocation for One Portfolio

Stage Target Calculation

ModeFormula
% of Buckettarget = stage_demand × pct ÷ 100
% of AOPtarget = Total_AOP × pct ÷ 100
M€ Allocationtarget = entered amount directly

Programmes are funded whole, in merit rank order, until the stage target × (1 + tolerance%) is reached. Each stage has its own independent target against the shared Total AOP ceiling.

Annual BCR Scoring Tiers

Annual BCR = Average Annual Benefit ÷ Requested Cost.
Avg Annual Benefit = Quantified Benefit ÷ Duration (default 3 years if not supplied).

Carry-Over (P2) Funding Cap

carryFundCap = min(Requested, Carry Over Baselined)

P2 eligibility: newCarry = "Carry Over" AND baselined > 0 AND priority = Must Do or Must Have AND category ≠ Decomm.

P2 RoI slider sets minimum threshold — carry-overs below threshold are pushed to P4.

Organisation IT Charge (One Portfolio)

Org IT Charge = Programme Funded Amount + Operations TCO

The Enterprise-Wide (EW) charging key distributes cross-BU programme costs proportionally. Each sub-org fraction = raw value ÷ total raw sum from the "Enterprise-wide charging" row in the source workbook.

PMI Programs

Programs with type = "PMI" are excluded from the prioritisation engine:

  • Auto-funded on top of the AOP budget (not charged to any BU)
  • Shown as a separate KPI on the Scenario tab
  • Not included in stage demand, merit ranking, or lever targets

Partial Scope

unfunded = requested − final

Always a manual decision — the engine allocates whole programmes only. Partial scope decisions are logged in the decision log.

Scenario Methodology

Explains the mechanics of scenario building and lever configuration. For actual scenario outcomes, use the Program Data tab filtered by Status.

Four Priority Stages

P1 · Legal & Compliance

Must-do regulatory and LFR compliance demand. CCB exception rules apply. Funded at ≤100% of bucket by default.

P2 · Carry Over

High-value carry-overs with baselined commitments. Funded up to min(Requested, Baselined). RoI slider controls minimum threshold.

P3 · Sustain & Hygiene

Change & Sustain and Continuous Improvement. Change & Sustain funded first within P3.

P4 · Value Portfolio

All remaining new demand. Merit-ranked by composite score. Merit floor (default 45) controls minimum inclusion threshold.

Preset Scenarios

PresetStrategy
Optimal SegmentationBalanced across all stages. Auto-computes LFR ceiling. Default starting point.
Protect CommitmentsMaximum LFR and carry-over. Sustain fully funded. Value at minimum.
Balanced PortfolioEvidence-based balanced approach. LFR cap applied, sustain 75%, value 15% AOP. Default for reporting.
Maximum BenefitBCR-weighted scoring (60% BCR weight). Sustain reduced. Maximises hard benefit output.

ExCo Trade-Off Cockpit

  • Enter a target budget per ExCo leader
  • Positive delta: includes additional P4 by merit (highest first)
  • Negative delta: excludes P4 by merit (lowest first)
  • Only affects P4 within selected ExCo demand
  • All decisions are logged; Reset clears all trade-off values
  • Total AOP is never modified

Manual Overrides

  • Include: funded even if below merit floor or stage target full
  • Exclude: unfunded even if normally selected
  • Partial scope: funded at less than full request
  • Excluding a funded programme does not auto-fund the next (“no silent refill”)
  • All decisions logged with reason, origin, and timestamp
