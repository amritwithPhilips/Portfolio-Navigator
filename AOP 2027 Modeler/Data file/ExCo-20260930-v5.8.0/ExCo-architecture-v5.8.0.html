ExCo decision view architecture

One scenario with two working views

ExCo opens a concise company decision view. Portfolio analysts retain all six tabs for detailed configuration, Programs review and Operations analysis. Both views operate on the same current scenario and shared finance result. No separate executive calculation model is introduced.

Meeting journey

  1. Company position. Read five KPIs, funded priority amounts and receiving organisation costs. Total IT includes base Programs, PMI and Operations; unallocated is already included.
  2. My portfolio. Select one of 16 accountable leaders, review funded and deferred Programs and open source IDs. This ownership view does not redistribute receiving-BU costs.
  3. Compare options. Compare the approved baseline, best tested lever configuration and current scenario. Save the current scenario before creating the recommended draft.
  4. Decisions. Preview a leader/stream trade-off or a discretionary Programs funding amount with rationale. Inspect exact financial changes, then apply or cancel. Save, export and finalise the meeting scenario.

State and transaction boundaries

The ExCo extension reads AOPApp.getState() and routes changes through the existing transaction, trade-off, save, export and undo functions. The original render publishes a change event; the ExCo view re-renders from the shared state. Recommendation analysis is embedded with the Programs source hash.

Preview uses a proposed copy. Apply compares scenario ID, revision and source hash against the preview, preventing stale decisions after an intervening edit. A finalised scenario blocks edit commands; a new working version retains parent lineage. The local version storage namespace is separate from v5.7.0.

Programs values and scenarios drive recipient fractions. Operations uses its fixed source allocation. EW uses the approved corrected BU row 276 percentages, leaving the residual visible. PMI is separate on top. Source references, source request and source merit remain distinct from scenario edits.

Release scope and future decisions

The architecture is implemented in the new standalone v5.8.0 HTML. This release retains offline scenario ownership, local persistence and source-linked exports. Central approval authority, multi-user collaboration, delivery capacity constraints and dependency-aware optimisation would require additional requirements and source inputs; they are not implied by this build.
