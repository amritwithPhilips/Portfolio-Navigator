4. Total AOP Protection
The Total AOP (M€) field changes ONLY via manual user edit. No automated process may modify it.
4.1 Trade-off Apply behaviour
ExCo Trade-off Apply button includes/excludes P4 programmes by merit ranking.
Apply does NOT modify the Total AOP budget. It only changes programme inclusion/exclusion.
The previous behaviour (Apply increased Total AOP by the sum of trade-off deltas) is removed.
4.2 "On top off AOP" KPI
"On top off AOP" shows the delta between actual allocation and the user-set budget.
Tabs 3 & 4: displayed as a separate KPI below the Committed Hard Benefits tile.
Tab 2: Allocated AOP shows "On top off: +X M€" (red) when over budget, or "Under budget: X M€" (green) when under.
Red indicates over-budget; green indicates under-budget.
4.3 Manual budget edit
The Total AOP input field on Tab 2 is the ONLY mechanism to change the budget. Presets do not change it. Trade-off Apply does not change it. Only direct user input changes it.

10. Prioritization Logic (unchanged from v4.0)
10.1 Four-Priority Funding Structure
Every demand row is classified into exactly one of four priorities. Gate 0 checks evidence. Classification is deterministic and data-driven.

10.2 Evidence Gate 0
Automatic funding holds. See PRD v4.0 Section 2.2 for complete hold conditions (11 hold types). Key changes since v4.0: review threshold at 10.0x (raised from 5.0x in v3.2).
10.3 Funding Algorithm
Sort all rows by priority (P1->P4) then ranking within priority.
Fund each eligible row at full requested amount if stage and portfolio budgets have capacity.
Stage limit = target x (1 + tolerance/100). Portfolio limit = Total AOP x (1 + tolerance/100).
P2: fund at min(Requested, Carry Over Baselined), not full request.
Tolerance default: 0.0% (exact budget).
Manual overrides after automatic: additions additive; exclusions do not refill silently.
10.4 Merit Scoring Framework (5 components)
0-100 composite score. Formula: Score = sum(raw_i / max_i x weight_i). Weights must sum to 100.0.
