The Total AOP (M€) field changes ONLY via manual user edit. No automated process may modify

change it. Trade-off Apply does not change it. Only direct user input changes it.

• Sort all rows by priority (P1->P4) then ranking within priority.

• Manual overrides after automatic: additions additive; exclusions do not refill silently.

Finance calculation module — v5.7.0 
The finance module is the calculation authority for Programs allocation and combined Programs 
+ Operations recipient cost. The source-accountability view and the receiving-BU view represent 
the same cost and must never be added together. 
Confirmed default and charging key 
The Optimal default budget is 100 M€. LFR retains the verified share; Carry Over uses approved 
baseline caps without an ROI threshold; Sustain is 60% of its bucket; Value uses the remaining 
available budget; IT Simplification is optional and inactive by default. Manual changes retain any 
overspend visibly. PMI is on top. 
EW charge to recipient b = funded EW Programs × charging fraction b. The BU row 276 
percentage formulas sum to 0.001 because recipient values totaling 40 are divided by 40,000. 
The confirmed correction multiplies each source fraction by 1,000. It preserves the exact 
22.63033175355452% unallocated share. Display rounding does not change the calculation. 
FIN-01 
One exact financial ledger feeds all six tabs, Portfolio Inclusion Table, both ExCo Trade-off 
Cockpits, AOP2027: Programs Demand Overview, Organisation IT Cost Allocation: Programs + 
Operations, and exports. 
FIN-02 
Separate demand selection from allocation. First compute requested, automatic, manual, final 
and unfunded for every active Programs record. Then allocate final funding using the 
appropriate source key. Allocation never changes merit or funding. 
FIN-03 
Single BU: use the row’s exact spend-allocation percentages, including sub-BU recipients. A 
confirmed sole recipient can receive 100% only when the source establishes that recipient; 
never substitute the requesting organisation for a missing charge key. 
FIN-04 
Cross BU: allocate final amount using the record’s exact percentages from SPEND ALLOCATION 
BY BUSINESS UNIT. Validate each recipient and row total. Do not redistribute an incomplete key 
automatically. 
FIN-05 
Indirect Cross BU follows its own source allocation, including Not allocated to BU. The 
requesting Function/Region remains the accountable origin. No fallback to the EW key is 
applied. 
 
 
FIN-06 
Enterprise-wide: isolate the Enterprise-wide charging row and apply its validated percentage 
vector to funded EW amounts. Retain both source Function/Region and recipient BU for drill-
down. 
FIN-07 
PMI remains funded on top of the 100 M€ envelope, separately identified and not charged to 
BUs. Unknown types remain explicitly unmapped until a valid source routing exists. 
FIN-08 
Retain exact source percentage precision. Apply the confirmed 1,000× correction only to an EW 
vector totaling 0.001; accept a fraction vector totaling 1 directly. Other EW totals are 
exceptions. BU row percentages are never silently normalized. Missing balances remain 
Unallocated. 
FIN-09 
Programs total uses investment spend, not operating-expense-only cost. Source capitalization 
and expense splits may be shown separately; spend = capitalization + expense. Do not substitute
