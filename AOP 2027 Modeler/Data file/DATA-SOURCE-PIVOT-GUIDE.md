## 5. Structural Compatibility Checks

Before running the pipeline, verify that the Consolidated Live file preserves these structural requirements:

### 5.1 Sheet Names (Critical)
`engine.js` line 18 expects exactly two sheets: **`EW`** and **`Bu`** (case-sensitive). If the Consolidated Live file uses different sheet names (e.g., "Enterprise Wide", "Business Unit"), `engine.js` normalize() will fail silently with 0 records.

**Check**: Open the XLSX → verify tab names are `EW` and `Bu`.

### 5.2 Header Row Layout
- **EW sheet**: Headers in row 1 (0-indexed row 0)
- **Bu sheet**: Headers in row 4 (0-indexed row 3), with sub-headers in rows 2-3

`engine.js` normalize() line 23-24 skips the first row as headers and processes data from row index 3+.

### 5.3 Required Column Headers

The engine uses flexible column matching (case-insensitive `includes()` on line 22), but these column names must be present or aliased:

| Required Column | Aliases Recognized |
|---|---|
| `Item No.` | `item no.` |
| `Planisware ID` | `planisware id` |
| `Organization setting demand [BU, Region, CoE]` | `organization` (partial match) |
| `Initiative name` | `initiative name` |
| `Type` | `type` |
| `New initiative or Carry-over` | `carry-over`, `carry over` |
| `Category` | `category` |
| `Leading IT Platform` | `leading it platform` |
| `Investment Area` | `investment area` |
| `Priority` | `priority` |
| `IT Investment Requested 2027 [k EUR]` | `it investment`, `requested` |
| `Quantified Benefits (in K EUR)` | `quantified benefits` |
| `Impact and Cost of Not Doing` | `impact and cost` |
| `Problem Statement` | `problem statement` |
| `Scope` | `scope` |
| `Overall AOP decision` | `overall aop decision` |
| `Decision Band` / `Waste\nband` | `band` (partial match) |

**v4.x additional columns** (used by extract_data.py):
- `LFR & Compliancy year`
- `LFR & Compliancy (Name)`
- `Big Bets`
- `RoI`
- `Payback`
- `Baselined` (column P in Bu sheet)

### 5.4 Organization Value for HPM
HPM rows are identified by: `"Monitoring - HPM (MCH)"` in the Organization column. If the Consolidated Live file uses a different label (e.g., `"HPM"` or `"Monitoring - HPM"`), the engine will still process rows but they will appear under a different org grouping. Verify the org string matches.

## 8. Scenario and Override Impact

### 8.1 Saved Sessions
Existing saved scenarios reference `sourceHash: 4ca3c6d4...`. When loaded against the new source:
- `engine.js` `refreshPreview()` (line 115) will detect changed fingerprints
- Changed records get `state: 'needs-review'` in manual overrides
- New records added, removed records flagged
- **Action**: All saved scenarios must be reviewed after pivot

### 8.2 Finalised Scenarios
Finalised scenarios freeze the source hash and cannot be refreshed. They remain valid historical records of the 15926 source. The new source creates new scenarios from scratch.

### 8.3 Conference Decisions
BU Led conference attendees (including HPM: `"Ajay Parkhe / Michael Meissner"`) are hardcoded in `build_v4.py` and the v4.x HTML files. These are **not affected** by the source pivot.

## 9. Risk Matrix

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Sheet names changed in Live file | Medium | **Critical** — 0 records extracted | Validate sheet names before running pipeline |
| Column headers renamed | Medium | **High** — missing fields, wrong values | Run structure check script (Section 5) |
